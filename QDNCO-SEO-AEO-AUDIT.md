# qdnco.com — SEO / AEO Audit

**Audited:** 2026-09-18
**Subject:** QD & Co. portfolio & marketing site (`~/Desktop/QD&Co`), 103 pages
**Note:** This file documents the *qdnco.com* marketing site. It is stored here for
convenience and does not describe RigaChat.
**Method:** Static analysis of the built `dist/` output — sitemap parity, canonical
tags, JSON-LD parsing, internal link graph, image hygiene, head resources — plus the
project's own `audit-seo.mjs` and `audit-links.mjs`. No live crawl, no Search Console
or CrUX field data. Rankings are asserted by the site owner and were not verified.

---

## Verdict

The content and semantic layer is genuinely excellent — top decile. The delivery
layer is the weak point, and it is the part Google measures directly. Nothing is
broken. The gap is between a near-perfect information architecture and a homepage
that compiles JSX in the browser.

## What is genuinely strong

### Technical foundation — near flawless

| Check | Result |
|---|---|
| Pages on disk vs. URLs in sitemap | 103 vs 103, **zero** discrepancy either way |
| Orphan pages (no internal inbound link) | **0** |
| Duplicate titles | **0** |
| Duplicate meta descriptions | **0** |
| Pages missing a canonical tag | **0** |
| Pages missing a meta description | **0** |
| H1 per page | exactly 1 on every page |
| JSON-LD blocks that fail to parse | **0 of 97** |
| Images missing `alt` | **0 of 202** |

That is a cleaner baseline than most agency sites ever reach.

### `.htaccess` is the best-reasoned file in the repo

Generated by `build-dist.mjs`. It:

- 301s `www.qdnco.com` → apex, and forces HTTPS, with HSTS at `max-age=31536000`
- disables LiteSpeed's server-side page cache (`CacheDisable public /`) — which is
  exactly what serves a stale `index.html` after a deploy
- caches assets for **one day, not one year**, with a comment correctly noting the
  filenames carry no content hash, so `immutable` would strand an updated logo
- sets `no-cache` on `robots.txt` and `sitemap.xml` so crawlers never get them stale

It also knows `_headers` is Netlify/Cloudflare syntax that LiteSpeed ignores, and
ships both deliberately. That is host-specific care that is rare.

### The AEO work is the real asset

`llms.txt` (161 lines) and `llms-full.txt` (127 KB) are exceptionally citable —
named founder, phone, email, and explicit published pricing (₹75,000–₹1,25,000
Phase 0; ₹550 per qualified lead, tiering to ₹495/₹450) plus a five-part definition
of a qualified lead.

Answer pages lead with a direct answer in sentence one, then give concrete
arithmetic — e.g. on a ₹1cr unit, a 2% channel-partner commission is ₹2,00,000
versus roughly ₹40,000 of media at ₹400 CPL and 100 leads per booking.

Several answers include an explicit **"The honest version of that comparison"**
section that concedes the counter-argument. That self-limiting framing is a strong
citation signal for LLMs and is the most likely reason AEO performance is good.

### Crawler posture and schema depth

- `robots.txt` explicitly welcomes GPTBot, OAI-SearchBot, ChatGPT-User,
  PerplexityBot, ClaudeBot, Google-Extended, Applebot-Extended, Bingbot,
  Amazonbot and meta-externalagent.
- `Organization` + `LocalBusiness` dual-typed, with full `PostalAddress`,
  `GeoCoordinates`, `areaServed`, `knowsAbout` and `alternateName`.
- 96 `BreadcrumbList`, 106 `Question`/`Answer` pairs, 55 `DefinedTerm`, 88 `Article`.

## Findings, ranked

### 1. 96 of 103 pages declare a Twitter card but have no `og:image`

Every page sets `twitter:card = summary_large_image`. Exactly **one** page in the
entire site has an `og:image` (`/shots/indium.jpg`).

Every share on LinkedIn, X, WhatsApp and Slack therefore renders as a bare text
link with an empty image well. For a marketing agency this is both a direct CTR
loss and an optics problem.

**Fix:** `site-shell.mjs` already templates the head — add `og:image`,
`og:image:width`, `og:image:height` and a default share image. Highest
impact-to-effort item on this list.

### 2. The homepage loads Babel standalone and compiles JSX in the browser

From `dist/index.html`:

```
cdn.tailwindcss.com                      ← JIT compiler, explicitly not for production
unpkg.com/react@18.3.1/umd/...           ← UMD build from CDN
unpkg.com/react-dom@18.3.1/umd/...
unpkg.com/@babel/standalone@7.29.0       ← ~3 MB, compiles JSX at runtime
unpkg.com/framer-motion@11.11.17/dist/framer-motion.js   ← full, unminified
unpkg.com/hls.js@1.5.17
```

`dist/` has **no `assets/` directory** — the Vite bundle is never shipped.
So `package.json` declares React 19 and `npm run build`, while the live homepage is
React 18 from a CDN, transpiled client-side by Babel.

Page weight: **656 KB of HTML** (273 KB of it inline `<script>` across 12 blocks,
89 KB inline `<style>`, 35 KB inline SVG across 49 elements), plus roughly 4 MB of
third-party JS across five render-blocking origins.

**Important qualification — this does not hurt indexing.** `#root` is fully
prerendered with real markup and the raw HTML contains 29,365 characters of body
text. Crawlers see the complete page without executing JavaScript. This is purely
an LCP / INP problem — but Core Web Vitals is a live ranking factor, and this is
the only item on the list that is real work.

### 3. `audit-links.mjs` has two bugs, and its one reported failure is a false positive

It reports:

```
BROKEN  guides/real-estate-performance-marketing-bangalore.html
     -> /data/bangalore-developer-marketing-market-size.html
```

That file exists at `dist/data/bangalore-developer-marketing-market-size.html`.

**Bug 1 — root-relative paths resolve wrongly.** The checker does
`path.join(base, u)` where `base` is the *containing* directory. A root-relative
`/data/...` referenced from `dist/guides/` resolves to `dist/guides/data/...`.
Root-relative hrefs must resolve against `DIST`.

**Bug 2 — most of the site is never checked.** The scan covers only `index.html`,
`legal/` and `guides/`. Not checked: `answers/` (46 pages), `work/`, `areas/`,
`compare/`, `glossary/`, `data/`, `pricing/` — roughly 75% of the site.

The comment directly above that loop reads *"a hardcoded list is exactly how the
guides would have shipped unchecked"* — but the list is still hardcoded to two
directories.

### 4. Image hygiene

| Metric | Value |
|---|---|
| Total images | 202 |
| Missing `width`/`height` (CLS risk) | 76 (38%) |
| No `loading` attribute | 168 (83%) |
| WebP / AVIF files | **0** |
| JPG / PNG files | 40 |
| `portrait-cutout.png` | **1.37 MB** single file |
| `shots/` + `brands/` | 3.9 MB combined |

`optimise-assets.mjs` exists but has clearly not been run against the current asset
set. The homepage audit alone reports 64 images missing dimensions and 55 not lazy-loaded.

### 5. Answer pages have exactly one inbound internal link each

Every answer is reachable only from the `/answers/` hub.

- `answers/how-much-does-a-real-estate-marketing-agency-cost.html` — high commercial
  intent — has **1** inbound link.
- `legal/disclaimer.html` has **203** (sitewide footer).
- `index.html` 300, `answers/index.html` 140, `work/index.html` 115.

Cross-linking related answers to one another would redistribute that meaningfully
and deepen the topical cluster.

### 6. Entity signals are thin where it counts

`sameAs` currently lists only:

```
Organization → facebook.com/profile.php?id=61583765303879   (not a vanity URL)
               instagram.com/qdnco.official/
Person       → linkedin.com/in/v-s-kavshik                  (personal, not company)
```

- **No Google Business Profile link** — the single biggest local-SEO gap for a
  Bengaluru business targeting "real estate marketing agency Bangalore".
- NAP appears on only **4 of 103 pages** rather than in the sitewide footer.
- Business email in schema is `qdnco01@gmail.com` — a weak trust signal versus a
  domain address.
- No LinkedIn *company* page, YouTube, or Crunchbase entry to consolidate the entity.

### 7. Smaller items

- **Stale sitemap.** All 103 `<lastmod>` values are `2026-09-09`, while `llms.txt`
  reports `2026-09-13`. Content moved; the sitemap did not.
- **31 titles exceed 60 characters** and will truncate in SERPs.
- **1.49 MB of the site's 3.31 MB of HTML is inline `<style>`** — 45% of all HTML,
  the same block repeated on every page. Extracting it to one cached external
  stylesheet would cut total HTML by roughly 45% and let it cache across navigations.
- **`verify.mjs` cannot run** — `puppeteer-core` needs an `executablePath` or
  `channel` that is not configured. A DX gap, not an SEO one, but it means the
  browser-based verification step is currently dead.
- **27 `FAQPage` blocks will not produce rich results.** Google restricted FAQ rich
  results to authoritative health/government sites in 2023. Keep them — they still
  earn their place for LLM parsing — but do not expect SERP features from them.
- **Canonical URLs use the `/pricing/index.html` form** rather than `/pricing/`.
  Sitemap, canonicals and internal links all agree, so signals are consolidated and
  this is not currently harming anything. It is only a concern if an external link
  or share ever uses the directory form, which canonicalises correctly anyway.
  Cosmetic, not urgent.

## Recommended order of work

| # | Action | Effort | Impact |
|---|---|---|---|
| 1 | Add `og:image` to the shared head template in `site-shell.mjs` | Trivial | High — fixes 96 pages at once |
| 2 | Fix the two `audit-links.mjs` bugs | Small | High — you are blind on 75% of links |
| 3 | Run `optimise-assets.mjs`; add dimensions + `loading="lazy"`; convert to WebP | Small | Medium — CLS and LCP |
| 4 | Regenerate the sitemap so `lastmod` reflects real content dates | Trivial | Low–Medium |
| 5 | Create a Google Business Profile; add to `sameAs`; put NAP in the footer | Small | High for local |
| 6 | Cross-link the answer cluster | Medium | Medium |
| 7 | Ship the Vite bundle instead of the Babel/CDN stack | **Large** | High — Core Web Vitals |
| 8 | Extract the repeated inline CSS to one cached stylesheet | Medium | Medium |

Items 1–5 are mechanical and low-risk and can go in a single pass. Item 7 is a
build-pipeline change and should be reviewed on its own.
